# 대화 규칙 테스트

`chat-rules.js`(대화 권한 규칙)를 실제 SQLite 위에서 무작위로 두들겨 보는 시뮬레이터입니다.

```bash
./test/run.sh              # 기본 시드 12개 × 10,000회
./test/run.sh 42           # 특정 시드만
node test/chat-sim.js 42   # 상세 통계까지
```

**Node 22 이상**이 필요합니다 (`node:sqlite`). 실패하면 종료 코드 1을 반환하므로 CI에 그대로 걸 수 있습니다.

## 왜 이렇게 만들었나

이 테스트는 규칙을 **베끼지 않고 `chat-rules.js`를 그대로 import** 합니다.
예전엔 시뮬레이터가 SQL 사본을 들고 있었는데, 서버의 `DM_COST` 값을 옮기지 않아
있지도 않은 과금을 검증한 적이 있습니다. 사본이 있으면 서버만 고쳤을 때
테스트는 통과하는데 실서비스는 틀린 상태가 됩니다.

`server.js`와 이 테스트가 같은 함수를 쓰므로, 규칙을 바꾸면 테스트가 즉시 반응합니다.

## 검증하는 불변식

**1:1 대화**
- 허용되지 않는 관계로는 스레드가 열리지 않음
  (실행이 끝난 뒤 모든 스레드의 **최초 메시지**까지 되짚어 재검사)
- 오픈매치를 같이 뛴 것만으로는 대화가 열리지 않음
- 대화는 무료 — 캐시가 1원도 움직이지 않고, `cash_ledger`에 한 줄도 남지 않음
- 차단한 상대에게는 보낼 수 없음
- 읽음 처리 후 안 읽은 메시지가 남지 않고, 메시지 순서가 뒤집히지 않음

**안읽음 집계 (`/me/unread`)**
- 1:1 만 센다 (`total` = `dm`)
- 원본 테이블 집계와 일치하고, 음수가 나오지 않음

> 클럽 단체방은 만들지 않기로 했습니다. 대화는 1:1 뿐이고,
> 클럽 공지는 '소식', 참석 확인은 '일정'이 맡습니다.
> 클럽은 여전히 등장하는데, `shareClub()`(같은 클럽 회원끼리 대화 가능)을
> 검증하려면 클럽 소속 관계가 필요하기 때문입니다.

## 한계

단일 스레드라 **동시성은 검증하지 않습니다.** 두 기기에서 같은 순간에
같은 방에 쓰는 경우의 경합은 이 테스트로 잡히지 않습니다.

## 규칙을 바꿀 때

1. `chat-rules.js`만 고칩니다 (`server.js`에는 규칙 SQL이 없습니다).
2. `./test/run.sh`를 돌립니다.
3. 의도한 변경이면 `chat-sim.js`의 `expectCanStart()`도 함께 고칩니다 —
   이 함수는 SQL과 무관하게 기대값을 따로 계산하는 교차 검증용이라,
   여기까지 고쳐야 테스트가 의미를 가집니다.
